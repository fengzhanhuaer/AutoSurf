# NetSurf

版本 0.4.30。点击 Chrome 工具栏中的 NetSurf，在浏览器主窗口打开 Dashboard 标签页；重复点击复用已打开的 Dashboard。

刷新与签到按共用超时支持弱网环境；只读页面遇到一次瞬时网络或网关错误会重试。单站“签到”无需预先打开网站，插件会创建后台标签，完成或超时后关闭；等待期间保留上次账号数据。

概览提供“刷新数据”和“一键签到”。批量刷新仅处理今天尚未成功刷新账号数据的启用站点；一键签到跳过今日已确认签到、无需签到和仅刷新站点。两种成功记录独立，按本机日期切换；失败不标记成功，可重试。逐站“重新检查”仍可强制刷新。批量操作串行执行，结束关闭自建后台页，不关闭原有页面。

概览操作列提供“打开 / 刷新 / 签到”；仅刷新或无需签到站点只显示“打开 / 刷新”，不重复按钮。逐站“刷新”可随时强制在后台读取该站数据，不提交签到，不受批量操作的当天成功跳过限制。

概览表格较宽时操作列固定在窗口右侧，打开、刷新和签到按钮仍保持可见；其他数据列可横向滚动查看。

刷新失败只更新检查错误提示，不覆盖旧账号字段及数据更新时间；成功时仅合并读取到的有效字段。KEEPFRDS 从本人页头括号读取当前等级（例如 Insane User），忽略 Next class、账号年龄等升级要求；旧缓存中的错误等级也不再展示，不将下一等级当成当前等级。

OpenCD 与 U2 的人工验证签到也内置仅刷新；普通站点保留各自开关。M-Team、朱雀、肉丝、SunnyPT 使用对应资料接口；肉丝/SunnyPT 的签到按站点接口提交一次并核验，结果未确认时不重发。朱雀仅监听当前账号资料请求，将等级和数值传给插件，不读取或保存请求头、账号令牌及其他接口响应；刷新使用临时后台页让网站客户端加载最新资料，原网页保留。

“刷新数据”按启用站点逐个在后台检查；没有站点页时创建非激活临时标签，检查后关闭，已有页面保留。刷新不提交签到，不占用签到重试次数，可重复执行。请求失败或资料字段缺失时保留已有数据；“逐站检查详情”显示具体原因、HTTP 状态和识别到的签到入口，并提供每站独立的“重新检查”。仅刷新站点显示“已刷新”或“待刷新”，不会计入签到完成数量。

CrabPT、HDDolby、憨憨、火花、PTTime、青蛙、杏坛分别识别本站签到奖励名称；HDCity 识别 Check in，HDArea 识别本人用户区的内联签到。PTTime 的已知签到参数只允许匹配本人资料 ID，拒绝其他账号和额外参数。M-Team 和朱雀使用当前账号资料接口读取数据，接口失效显示登录或请求错误，不把空白应用首页判定为成功。任务页等待导航至当前站点且文档可读取后检查，补充账号/等级请求最多等待 5 秒，失败时保留首页状态和已读字段，并在检查详情显示原因。

## 加载或更新

在日常使用的正式版 Google Chrome 中打开 `chrome://extensions/`，开启开发者模式，加载已解压的目录 `D:\Code\AutoSurf\extensions\netsurf`。已安装时点击扩展卡片上的“重新加载”；会同时刷新已有 Dashboard，保留当前菜单和已保存设置，然后刷新 PT 页面。仅刷新网页不会重新加载扩展后台，请以 Dashboard 左下角版本为准。无需构建或安装依赖，需要 Chrome 130 或更新版本。

## 导航与操作

左侧为一级导航，上方为对应的二级菜单，各菜单切换实际内容：

- PT站点：概览、站点管理。
- 设置：常规（自动签到、备份与还原）、关于。

站点管理列出 AutoSurf 清单中的全部 64 个 PT 站点，可搜索名称或域名，每一行有独立的“启用”和“仅刷新”开关。保留已有站点启用状态，新加入的站点默认停用；普通站点仅刷新默认关闭，启用时申请该站点主机访问权限。需要人工验证的特殊站点可内置仅刷新规则，目前 52PT、OpenCD、U2 固定仅刷新，显示“内置仅刷新”，不能关闭；旧设置及还原备份也不能让这些站点自动签到。

概览以表格展示已启用站点的签到状态、用户等级、魔力值、做种积分、上传量、下载量、分享率和检查时间，每行提供打开与签到操作。魔力值和做种积分分别显示实际数值，去掉明细链接，保留千位分隔和小数。账号数据读取当前登录账号的首页信息区及其同源个人资料页，未知字段显示 `—`，未经今日核验的状态不计为完成。关闭站点后隐藏该行，关闭全部站点显示空状态。打开 Dashboard 只检查数据；自动签到开启时后台按已保存计划执行。

等级栏仅显示等级名称，例如 `(小学)Power User` 显示为 `Power User`，去除括号前缀和同一资料单元格中的校验、加群及规则说明；新抓取与已保存的等级都按此显示。只有等级帮助链接时，读取等级图标或同源等级页当前链接对应的等级，例如 TJUPT 的 `classes.php#6` 对应行；不会按“已达到此等级”选择其他等级，也不会点击升级。

PT站点 → 站点管理中，每个站点独立设置“仅刷新”，默认关闭；设置页没有全局仅刷新开关。该站开启后，启用该站点立即排队刷新账号数据，对已启用站打开仅刷新也会刷新一次，即使自动签到总开关关闭也会执行这一次刷新；自建任务页结束后关闭，已有页面保留。该站的定时任务和行内“刷新”操作同样只读取数据，不提交签到，其他站点不受影响。关闭该站“仅刷新”后恢复正常签到行为，每站设置包含在备份和还原中，旧备份未包含时默认关闭。

清单包含各站域名、别名及已知签到路径，页面识别支持通用 NexusPHP 界面；无需每日签到的站点只检查账号页面。特殊页面未识别时显示“未识别”，不提交未知控件。列出 64 站不代表已完成全部站点的实际登录或特殊签到适配。

在概览点击对应站点的“打开”，切换到已有站点标签页，没有时新增一个标签页；Dashboard 保留。登录后可以“刷新数据”或点击对应行“签到”。站内安全验证需在站点网页完成，再检查结果。

站点列表上方只有一份“签到设置”，所有站点共用：当地开始时间（默认 08:00）、重试间隔（默认 300 秒，可选 30–86400 秒）、重试次数（默认 3，可选 0–10）、每次超时（默认 30 秒，可选 5–120 秒）。保存后作用于所有已启用站点；列表保留逐站启用/仅刷新开关与打开操作。旧版本 PigGo 的时间设置自动作为初始共用设置。超时覆盖自动任务打开页面、核验和签到；手动任务覆盖核验和签到。

自动任务逐站执行：没有现成站点页时只打开一个后台任务标签，提交后在同一次超时预算内核验结果，确认、失败或超时均关闭该任务页，再尝试下一站。未确认结果保留为待核实，不自动重复提交，不留下指向已关闭页面的核验计划。原本打开的页面和 Dashboard 保留；通过 Dashboard 主动打开正在执行的任务页会接管该页面并保留。任务标签所有权仅保存在当前浏览器会话，工作线程恢复时清理已记录的遗留页；旧版没有所有权记录的标签不会批量关闭。

任务页关闭或扩展重新加载后保留上次结果和原检查时间，没有站点页面不会把已有状态覆盖成“未打开”。旧版已被覆盖的状态若仍有今日确认标记，可以恢复“已完成”；无法恢复的检查时间显示 `—`，昨日缓存显示待核验。更新请使用“重新加载”，真正卸载会清除 Chrome 保存的扩展数据；当前备份文件仅包括设置及 Cookie，不包括签到历史。

Dashboard 启动先读取已保存的各站结果，后台检查尚未结束也能显示缓存；检查过程逐站更新表格，旧存储快照不会覆盖任务刚写入的新结果。

页面检查耗时时，自动签到及站点开关仍可点击，设置通过独立后台队列保存，刷新页面后保留。关闭开关会在待执行签到提交前再次检查。站点开关的保存和授权失败提示显示在列表上方；自动签到的失败原因显示在开关下方。还原备份期间暂时锁定设置，避免覆盖正在保存的变更。

设置已写入但计划重建失败时，开关保持已保存的状态，并显示“签到计划更新失败”及原因；此时需要处理提示后重新加载扩展，保存成功不代表调度已正常启动。后台响应格式不兼容时会明确提示重新加载扩展。

设置中的“启用自动签到”默认关闭。开启后 Chrome alarms 按共用计划到点执行，逐站复用已有标签页；没有时创建该站点的普通后台标签页。各站结果、执行锁和重试预算独立，当天完成会跳过，浏览器重启后恢复计划和未耗尽的重试。仅提交前的通信失败会按设置重试，登录/安全验证/验证码停止；提交结果不明只核验，不重复提交。Chrome 关闭时不能执行，休眠或延迟的闹钟在恢复后补检，不保证秒级准时。不依赖旧 AutoSurf 服务，也不启动专用 Chrome。

最近 50 次固定检查/签到结果仍在本地保存，已移除独立操作记录菜单；不保存网页正文或凭据到操作记录。

52PT 通过独立规则读取本人 User_Name 链接、等级图标及“传输”嵌套表格，解析等级、上传、下载和精确分享率；未提供做种积分时显示 `—`。内置仅刷新只读取账号资料，不访问滑块签到页；点“打开”进入当前 `/bakatest.php`，供用户手动完成滑块和签到。不会拖动滑块或提交签到。扩展更新时可替换已打开网页上的旧版脚本，不把旧脚本返回的状态误当成新版检查结果。

## 备份与还原

在设置 → 常规点击“备份”，按 Chrome 提示授予可选 Cookie 和所有 HTTP/HTTPS 网站访问权限后下载本地 JSON 文件，包含自动签到开关、共用签到设置、全部 64 个站点的启用状态，以及当前 Chrome 配置中所有网站 Cookie。包括未启用站点、非 PT 网站、HttpOnly 登录 Cookie 和分区 Cookie；不会因为站点清单或签到适配状态缩小范围。备份文件包含登录凭据，请妥善保存。

点击“还原”选择 NetSurf JSON 备份。整个文件先验证版本、设置范围及 Cookie 域名和属性，再写入；非法文件不改变设置或 Cookie。还原覆盖设置和备份中的同名/同域/同路径 Cookie，不删除备份之外的 Cookie。保留 Secure、HttpOnly、SameSite、会话/有效期、主机范围及分区属性，跳过已过期 Cookie。

还原期间关闭自动签到并清除各站旧完成缓存与锁，成功后恢复备份开关和计划。Cookie 部分写入失败会显示成功/过期/失败数量，保留原站点设置且自动签到保持关闭；Chrome Cookie API 不支持多条记录的事务回滚。还原后刷新相关网站，再检查登录和今日状态。文件上限 10 MB。备份不含操作记录、账号统计缓存和临时执行状态，兼容旧版单站备份。

## 登录与权限

使用当前浏览器登录。必需权限为 `storage`、`alarms`、`scripting` 和 `https://piggo.me/*`。其他 PT 站点在启用时申请对应主机权限；`cookies` 与全部 HTTP/HTTPS 主机权限在备份/还原时申请。通用内容脚本仅注册到已启用且已授权的 PT 站点；备份的全站权限不会向所有普通网站注入签到脚本。不申请 debugger 或 tabs 权限，不读取其他 Chrome 配置的 Cookie。

状态检查通过站点页面内的同源无缓存请求读取首页，提交前再次核对新状态。历史文字、昨日缓存不作为今日完成依据。当前页面的验证或登录提示优先，不用首页结果覆盖。单次操作保护按共用超时时间生效，执行状态按站点隔离，页面内也阻止重复点击。

AutoSurf → 正式 Chrome 的 Cookie 迁移为用户授权的一次性本地操作，不属于插件功能。2026-10-14 已备份 Default 配置的原 Cookie 库，迁入并加密回读核对 407 条，跳过 1 条已过期记录；恢复正式 Chrome 会话且不使用远程调试参数。迁移前隔离 Chromium 成功实际读取全部 408 条快照。各站点实际登录状态仍需在正式 Chrome 核验。
