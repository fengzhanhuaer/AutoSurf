# NetSurf

UBits、PTSBao 签到前复用最近五分钟内加载成功且包含账号数据的首页，避免再次请求首页耗尽签到预算；旧页面或错误页仍重新读取，提交后仍核验真实完成标记。

版本 0.4.89。点击 Chrome 工具栏中的 NetSurf，在浏览器主窗口打开 Dashboard 标签页；重复点击复用已打开的 Dashboard。

52PT 使用当前 `/bakatest.php`，避开首页已停用的旧链接，执行一次站内固定滑块和一次原生表单提交，再核验真实结果。提交期间不并行读取会更新校验令牌的签到表单；仍有未完成表单时不把成功文字当成完成。52PT 成功后仍展示表单、Audiences 首页仍保留签到入口，因此当天已核验且已结束的提交不会被刷新清除，也不会再次提交；跨日、无核验或未决记录不套用。仅刷新改为可独立设置，升级保留原开关。Audiences 签到页在任务预算内等待官方 Turnstile 自行完成；需要人工交互或验证超时则停止，不改写令牌或伪造验证结果。

海胆支持首页独立“每日打卡”按钮，沿站点原生流程提交一次。隐藏的奖励弹窗和 JavaScript 更新的“已经打卡”不作为完成证据，重新读取首页确认服务端状态，兼容完成后移除奖励弹窗的页面；魔力取当前余额而非站点统计。仅刷新设置仍独立生效，未确认操作不自动重发。

PTSBao 支持 `/attendance.php` 的 `imagestring`/`imagehash` 图片验证码表单：复用本地 OCR，一次打开表单、一次识别和一次提交许可；识别不可靠或表单、图片、权限发生变化立即停止。验证码不上传第三方、不记录到执行历史，提交后只读核验，不循环重试。

左侧“PT站点”下新增“定时任务”，预置 NodeSeek 与 InvitesFun，独立于 PT 站点和 PT 自动总开关。使用当前浏览器登录，每任务一个开关，每日 08:00 签到；两个任务初始均关闭，不会因升级擅自签到。概览提供打开、执行和一键执行，以及状态、上次结果和下次执行。

NodeSeek 沿用旧版固定奖励 POST `/api/attendance?random=false`，不抽取随机奖励；InvitesFun 仅点击 `.item-forum-checkin .CheckInButton--yellow`，以已签到绿色按钮或明确成功弹层确认。请求/点击前持久化单次许可，验证码和登录失败停止；提交后超时或工作线程重启只读核验，不重复提交。当日已核验成功会跳过，普通任务不进入 PT 统计。Chrome 必须运行，休眠或关闭不能保证准点，恢复后补检到期任务。

备份包含普通任务配置，不包含任务历史、提交记录或成功缓存；还原保留本机已有普通任务提交保护，避免重复操作，Cookie 部分还原失败时普通任务也会关闭。旧格式没有普通任务配置时保持关闭。

当日已有真实核验成功记录时，随后账号请求超时、结果页关闭或迟到的通信错误不会撤销“已完成”。刷新失败单独保留原因与原资料时间；重载可从当日核验记录恢复此前被错误覆盖的完成状态，不重新签到。无当日核验记录、跨天、仅刷新站点和真实验证/登录异常不套用此恢复规则。

海棠签到支持从首页进入签到页后，提交一次当日“立即签到”表单，不点击日历补签。阶段许可绑定本次任务、标签页和截止时间，先保存提交意图再点击；旧未决记录不会自动重发。核验同时读取当前页面与首页，首页请求慢不会挡住签到页已经出现的成功或验证提示；已打开的未决签到结果页优先保留并只读核验。

PigGo 的官方签到链接通过受控浏览器导航打开，仍限制同源、精确签到路径和单次操作许可。遇到已知雷池临时页面时，在任务超时内等待网站自身自动验证，不提前关闭任务页；明确连接失败或拦截立即显示需验证，不重复导航或调用挑战接口。

Free Farm 支持本站已适配的固定轨道滑块：许可绑定任务、页面及截止时间，只拖动一次，然后核验实际签到结果。未知结构、许可失效或拖动失败时停止；保留用户已有“仅刷新”设置，可在站点管理关闭以启用签到。不处理其他站点或第三方拼图验证。

HXPT 显式签到可定位本人隐藏菜单中的官方“签到得火花”链接，仍校验标签与同源路径，不点击其他隐藏控件；只读刷新不点击入口。HXPT、海棠、AGSV、PigGo 可复用已成功加载且含账号数据的近期根首页，避免再次预检重复请求慢首页；历史未决记录仍只读核验，不自动重发。

概览分别统计“今日签到”和“仅刷新”：签到分母仅包含已启用且可签到的站点，仅刷新设置及内置资料站点单独计数。只有今日已核验的签到成功或有效资料刷新计入相应完成数，旧缓存和失败结果不计入。

憨憨、海棠和 HXPT 的手动刷新及签到使用受控后台首页，保留用户原页面；读取成功加载的新首页，不再依赖旧消息页的重复首页请求。签到预检不补抓非必要等级资料，完整资料仍可通过刷新获取。临时页完成后清理，遇到验证仍需人工处理；失败提示附带脱敏请求阶段和耗时。

手动签到复用已有标签页时，结果核验使用配置的剩余超时，不再固定只等两秒；不会因此再次提交或把未确认改成成功。

憨憨从新版隐藏账号侧栏读取憨豆、分享率和传输数据；仅在用户发起签到、入口尚未显示时展开本人头像侧栏，普通刷新不会点击头像或签到入口。

签到结果核验保留当前页面已明确识别的成功，不被首页仍保留的签到入口或未识别结果覆盖；账号刷新仍保留新资料，验证和登录异常不会被隐藏。既有待确认记录不会直接改成成功，也不会自动重复提交。

HXPT 读取新版账号栏的火花和传输数据；JPopsuki 识别 `Up/Down` 统计，并从同源本人 `user.php?id=…` 资料页读取等级。海棠弱网刷新可复用刚加载且已有账号字段的页面，签到未确认时不据此假报完成。

HDSky 与 OpenCD 的已适配六位图片验证码使用插件本地识别；保留用户已有“仅刷新”设置，不自动关闭。未能可靠识别时停止，不自动换图或反复提交。

HDArea 从本人“欢迎回来”行中的 `[已签到]` 识别完成，不因该标记没有链接而显示未识别或重复签到。

## 加载或更新

在日常使用的正式版 Google Chrome 中打开 `chrome://extensions/`，开启开发者模式，加载已解压的目录 `D:\Code\AutoSurf\extensions\netsurf`。已安装时点击扩展卡片上的“重新加载”；会同时刷新已有 Dashboard，保留当前菜单和已保存设置，然后刷新 PT 页面。仅刷新网页不会重新加载扩展后台，请以 Dashboard 左下角版本为准。无需构建或安装依赖，需要 Chrome 130 或更新版本。

## 导航与操作

左侧为一级导航，上方为对应的二级菜单，各菜单切换实际内容：

- PT站点：概览、站点管理。
- 定时任务：概览、设置；NodeSeek、InvitesFun 每日签到。
- 设置：常规（自动签到、备份与还原）、关于。

站点管理列出 AutoSurf 清单中的全部 64 个 PT 站点，可搜索名称或域名，每一行有独立的“启用”和“仅刷新”开关。保留已有站点启用状态，新加入的站点默认停用；普通站点仅刷新默认关闭，启用时申请该站点主机访问权限。需要人工验证的特殊站点可内置仅刷新规则，目前 52PT、U2、CHDBits 固定仅刷新，显示“内置仅刷新”，不能关闭；旧设置及还原备份也不能让这些站点自动签到。

概览以表格展示已启用站点的签到状态、用户等级、魔力值、做种积分、上传量、下载量、分享率和检查时间，每行提供打开与签到操作。魔力值和做种积分分别显示实际数值，去掉明细链接，保留千位分隔和小数。账号数据读取当前登录账号的首页信息区及其同源个人资料页，未知字段显示 `—`，未经今日核验的状态不计为完成。关闭站点后隐藏该行，关闭全部站点显示空状态。打开 Dashboard 只检查数据；自动签到开启时后台按已保存计划执行。

等级栏仅显示等级名称，例如 `(小学)Power User` 显示为 `Power User`，去除括号前缀和同一资料单元格中的校验、加群及规则说明；新抓取与已保存的等级都按此显示。只有等级帮助链接时，读取等级图标或同源等级页当前链接对应的等级，例如 TJUPT 的 `classes.php#6` 对应行；不会按“已达到此等级”选择其他等级，也不会点击升级。

PT站点 → 站点管理中，每个站点独立设置“仅刷新”，默认关闭；设置页没有全局仅刷新开关。该站开启后，启用该站点立即排队刷新账号数据，对已启用站打开仅刷新也会刷新一次，即使自动签到总开关关闭也会执行这一次刷新；自建任务页结束后关闭，已有页面保留。该站的定时任务和行内“刷新”操作同样只读取数据，不提交签到，其他站点不受影响。关闭该站“仅刷新”后恢复正常签到行为，每站设置包含在备份和还原中，旧备份未包含时默认关闭。

清单包含各站域名、别名及已知签到路径，页面识别支持通用 NexusPHP 界面；无需每日签到的站点只检查账号页面。特殊页面未识别时显示“未识别”，不提交未知控件。列出 64 站不代表已完成全部站点的实际登录或特殊签到适配。

在概览点击对应站点的“打开”，切换到已有站点标签页，没有时新增一个标签页；Dashboard 保留。登录后可以“刷新数据”或点击对应行“签到”。站内安全验证需在站点网页完成，再检查结果。

站点列表上方只有一份“签到设置”，所有站点共用：当地开始时间（默认 08:00）、重试间隔（默认 300 秒，可选 30–86400 秒）、重试次数（默认 3，可选 0–10）、每次超时（默认 30 秒，可选 5–120 秒）。保存后作用于所有已启用站点；列表保留逐站启用/仅刷新开关与打开操作。旧版本 PigGo 的时间设置自动作为初始共用设置。超时覆盖自动任务打开页面、核验和签到；手动任务覆盖核验和签到。

签到任务逐站执行：没有现成站点页时只打开一个后台任务标签，提交后由插件在同一次超时预算内核验结果，已有站点页也执行相同核验。只有运行中显示“核验中”；取得当日完成证据才显示成功，超时或核验中断显示“签到失败”并记录原因，不留下最终“待确认”。这里失败表示本次任务未取得成功证据，不断言服务器一定没有执行。未决提交保护独立保留，当天再次点击签到或自动任务只读检查，不重复提交；只读检查取得明确完成证据后恢复成功。旧待确认及工作线程中断记录也由插件只读核验收尾。确认、失败或超时均关闭自建任务页，再处理下一站，不留下指向已关闭页面的核验计划。原本打开的页面和 Dashboard 保留；通过 Dashboard 主动打开正在执行的任务页会接管该页面并保留。任务标签所有权仅保存在当前浏览器会话，工作线程恢复时清理已记录的遗留页；旧版没有所有权记录的标签不会批量关闭。

任务页关闭或扩展重新加载后保留上次结果和原检查时间，没有站点页面不会把已有状态覆盖成“未打开”。旧版已被覆盖的状态若仍有今日确认标记，可以恢复“已完成”；无法恢复的检查时间显示 `—`，昨日缓存显示待核验。更新请使用“重新加载”，真正卸载会清除 Chrome 保存的扩展数据；当前备份文件仅包括设置及 Cookie，不包括签到历史。

Dashboard 启动先读取已保存的各站结果，后台检查尚未结束也能显示缓存；检查过程逐站更新表格，旧存储快照不会覆盖任务刚写入的新结果。

页面检查耗时时，自动签到及站点开关仍可点击，设置通过独立后台队列保存，刷新页面后保留。关闭开关会在待执行签到提交前再次检查。站点开关的保存和授权失败提示显示在列表上方；自动签到的失败原因显示在开关下方。还原备份期间暂时锁定设置，避免覆盖正在保存的变更。

设置已写入但计划重建失败时，开关保持已保存的状态，并显示“签到计划更新失败”及原因；此时需要处理提示后重新加载扩展，保存成功不代表调度已正常启动。后台响应格式不兼容时会明确提示重新加载扩展。

设置中的“启用自动签到”默认关闭。开启后 Chrome alarms 按共用计划到点执行，逐站复用已有标签页；没有时创建该站点的普通后台标签页。各站结果、执行锁和重试预算独立，当天完成会跳过，浏览器重启后恢复计划和未耗尽的重试。仅提交前的通信失败会按设置重试，登录/安全验证/验证码停止；提交结果不明只核验，不重复提交。Chrome 关闭时不能执行，休眠或延迟的闹钟在恢复后补检，不保证秒级准时。不依赖旧 AutoSurf 服务，也不启动专用 Chrome。

最近 50 次固定检查/签到结果仍在本地保存，已移除独立操作记录菜单；不保存网页正文或凭据到操作记录。

52PT 通过独立规则读取本人 User_Name 链接、等级图标及“传输”嵌套表格，解析等级、上传、下载和精确分享率；未提供做种积分时显示 `—`。内置仅刷新只读取账号资料，不访问滑块签到页；点“打开”进入当前 `/bakatest.php`，供用户手动完成滑块和签到。不会拖动滑块或提交签到。扩展更新时可替换已打开网页上的旧版脚本，不把旧脚本返回的状态误当成新版检查结果。

## 普通站点定时任务

在左侧 PT站点下方打开“定时任务”，上方为“概览 / 设置”。概览显示 NodeSeek、InvitesFun 的签到状态、上次结果和下次执行，每行仅提供打开和执行，顶部提供“一键执行”，没有刷新按钮。设置中每个任务仅一个开关，点击即保存；首次均关闭，开启时申请该站点访问权限。没有时间、周期或重试等高级输入，也不需要另点保存。任务独立于 PT 自动签到总开关，不计入 PT 完成数。

每日当地时间 08:00 自动签到，开启后会补检当天已到期的任务；当天已完成则跳过，后续固定次日 08:00，不随手动点击时间变化。旧版多日周期和自定义时间自动归一为每日计划，保留原开关、确认记录和提交保护。请先在原站登录，并保持 Chrome 运行。

开关先读取本扩展已保存的设置，不等待后台任务查询。授权时显示等待 Chrome 权限提示；拒绝、保存失败或通信超时都会恢复操作，不会因后台查询失败永久禁用开关。旧后台不兼容时会明确提示在扩展管理页重新加载；仅刷新 Dashboard 不会更新后台。

“执行”先核验再进行一次受控签到；“一键执行”按顺序运行已启用的任务，当天已确认完成的任务自动跳过，不会开启已关闭任务。单站返回失败或需验证仍继续其他任务；通信超时或异常则停止队列，显示原因并恢复按钮，避免状态不明时继续排队。NodeSeek 使用旧版固定奖励接口，InvitesFun 只点击限定签到按钮并核验成功控件。需登录或安全验证时停止该站提交，验证码仍需在原站人工完成。提交结果不明会记为执行失败，并保留当日提交保护，再次操作仅只读核验，不自动重发。自建后台任务页结束后关闭，用户已有或已接管的页面保留。最近 50 次执行记录仅内部保留，不再展示独立历史表。

Chrome 必须保持运行；休眠和关闭期间不执行，恢复后补检到期计划。扩展重载或浏览器重启会恢复计划；手动签到不会将后续计划时间平移到点击时间。任务配置随设置备份，执行记录和提交保护不导出；还原期间先停用任务，验证完成后按备份配置恢复，旧备份没有定时配置时保持停用。

NodeSeek 按 `/board` 本人签到栏的“今日还未签到”和“鸡腿 x 5”固定奖励控件识别，不依赖按钮叫“签到”；请求仍固定 `random=false`。InvitesFun 的绿色“已签到”按钮即使 disabled 也属于有效完成证据，但禁用的黄色按钮不可点击。状态核验超时会说明页面识别/脚本注入阶段及目标路径，不再统一隐藏成笼统加载失败。

## 备份与还原

在设置 → 常规点击“备份”，按 Chrome 提示授予可选 Cookie 和所有 HTTP/HTTPS 网站访问权限后下载本地 JSON 文件，包含自动签到开关、共用签到设置、全部 64 个站点的启用状态，以及当前 Chrome 配置中所有网站 Cookie。包括未启用站点、非 PT 网站、HttpOnly 登录 Cookie 和分区 Cookie；不会因为站点清单或签到适配状态缩小范围。备份文件包含登录凭据，请妥善保存。

点击“还原”选择 NetSurf JSON 备份。整个文件先验证版本、设置范围及 Cookie 域名和属性，再写入；非法文件不改变设置或 Cookie。还原覆盖设置和备份中的同名/同域/同路径 Cookie，不删除备份之外的 Cookie。保留 Secure、HttpOnly、SameSite、会话/有效期、主机范围及分区属性，跳过已过期 Cookie。

还原期间关闭自动签到并清除各站旧完成缓存与锁，成功后恢复备份开关和计划。Cookie 部分写入失败会显示成功/过期/失败数量，保留原站点设置且自动签到保持关闭；Chrome Cookie API 不支持多条记录的事务回滚。还原后刷新相关网站，再检查登录和今日状态。文件上限 10 MB。备份不含操作记录、账号统计缓存和临时执行状态，兼容旧版单站备份。

## 登录与权限

使用当前浏览器登录。必需权限为 `storage`、`alarms`、`scripting` 和 `https://piggo.me/*`。其他 PT 站点在启用时申请对应主机权限；`cookies` 与全部 HTTP/HTTPS 主机权限在备份/还原时申请。通用内容脚本仅注册到已启用且已授权的 PT 站点；备份的全站权限不会向所有普通网站注入签到脚本。不申请 debugger 或 tabs 权限，不读取其他 Chrome 配置的 Cookie。

状态检查通过站点页面内的同源无缓存请求读取首页，提交前再次核对新状态。历史文字、昨日缓存不作为今日完成依据。当前页面的验证或登录提示优先，不用首页结果覆盖。单次操作保护按共用超时时间生效，执行状态按站点隔离，页面内也阻止重复点击。

AutoSurf → 正式 Chrome 的 Cookie 迁移为用户授权的一次性本地操作，不属于插件功能。2026-10-14 已备份 Default 配置的原 Cookie 库，迁入并加密回读核对 407 条，跳过 1 条已过期记录；恢复正式 Chrome 会话且不使用远程调试参数。迁移前隔离 Chromium 成功实际读取全部 408 条快照。各站点实际登录状态仍需在正式 Chrome 核验。

### HDSky / OpenCD 图片验证码

自动签到核验到截止时间仍失败后，停止该次操作的自动开页和核验，不再因页面加载、重试闹钟或浏览器启动反复打开。保留未决提交保护，可手动刷新只读核验；未提交前的网络错误仍按原重试次数/间隔执行，下一天按每日计划处理。

HDSky 首页的六位字母数字签到图片使用插件捆绑的 ddddocr 模型与 ONNX Runtime WASM 本地识别，不需要旧 AutoSurf/Python 服务，不上传图片或记录答案。三种预处理至少两次输出一致才提交一次；识别失败、图片变化或超时停止，结果由站点明确完成标记核验，不自动换图重试。其他问答、滑块及安全验证仍须人工处理。

保留原有每站“仅刷新”设置；已开启时仍只刷新数据，不自动迁移或关闭它。要使用 HDSky 本地签到，可在站点管理关闭该站“仅刷新”。依赖版本、许可证和 SHA256 见 `vendor/ocr/README.md`。离屏页面仅在识别时创建，完成或失败后关闭释放模型。

OpenCD 使用首页精确签到入口和同源 `i_signin` iframe，仅识别 `frmSignin` 中与图片匹配的隐藏令牌及明确的签到按钮；不点击“算了”。填写和提交前重新检查令牌、表单、控件和图片，后台按 OpenCD 独立任务授权一次，实际完成链接才算成功。其他结构或人机验证不自动填写。
