## 二、总体架构

工具栏 action.onClicked → 串行打开/复用 dashboard.html → dashboard.js → 按 siteId 路由的后台消息 → 站点内容脚本。通过 runtime.getContexts 识别 Dashboard，包括二级路由，不申请全浏览器 tabs 权限。静态 HTML/CSS/JS，无需构建。catalog.js 保存源代码 PT_SITE_CATALOG 的 64 站快照；sites.js 将 scheduleConfig 的一份共用设置合并到各站启用状态，兼容旧 PigGo 配置。background.js 隔离各站结果、锁和持久化重试预算，Chrome alarms 使用同一套时间参数，恢复浏览器后重建闹钟；动态脚本仅注册到启用且授权的 PT 主机。backup.js 验证本地 JSON；后台要求 Cookie 及全部 HTTP/HTTPS 主机权限后查询 partitionKey:{}，覆盖当前配置所有网站及分区 Cookie。

0.4.1：前端分开管理页面操作忙碌与设置保存忙碌，耗时检查不禁用开关。后台设置使用 settingsQueue，检查/签到仍用 actionQueue，闹钟及内容脚本重建统一通过 scheduleQueue；备份还原同时排队获取设置执行权，前端锁定设置，避免覆盖。提交前重新检查最新启用及自动签到总开关。

0.4.2：onInstalled 更新事件查找本扩展 Dashboard，通过 tabs.reload 刷新旧文档，不更改其 URL 和路由，不刷新普通网页。设置持久化完成后，调度重建异常用 warning 返回，前端显示已保存及计划失败，后台响应不兼容单独提示扩展重载。

0.4.3：自动任务继续使用 actionQueue，storage.session 记录唯一任务标签所有权；加载、提交和结果确认共用超时预算，finally 关闭该标签后才进入下一站。用户原有页面不关闭，通过 Dashboard 主动打开任务页则接管并保留；未确认不自动重发，已关闭任务页不建立延迟核验闹钟。工作线程恢复先清理同一浏览器会话内遗留的任务页，不跨浏览器会话按旧标签 ID 误删。

新建任务页先创建空白标签并登记所有权，再导航站点。无已打开页面时 inspectSite 不覆写 lastResult；旧代码覆写为 no_tab 的记录若仍有今日 verifiedDay，可恢复确认状态至 confirmedDay，不造出检查时间。Dashboard 用确认日期或原检查日期判断今日完成，昨日结果不会变成今日完成。扩展重载不清空 activity；真正卸载的 Chrome 本地存储无法保证保留。

0.4.4：启动从 storage.local 读取所有站点的 lastResult 并立即显示，检查忙碌时 storage.onChanged 仍更新表格，但不覆盖整体进度提示。初始化的旧结果不覆盖已收到的新结果。用户原目录和扩展 ID 未改变，重载现有 Chrome 扩展后版本 v0.4.4，概览 20 项已完成已现场读取。

0.4.5：sites.level 统一提取等级名称并去除说明，资料页解析和 sites.profile 对缓存值的规范化共用该函数；保留 `(小学)` 等站点等级前缀。正式概览已读取 GradeVisible=true、HelpTextVisible=false。

0.4.6 设计：sites.number 提取数值前缀，profile 统一处理 bonus/seedingPoints 的缓存与新值；等级去掉括号前缀。仅从本人资料等级单元格或账号页头读取同源 classes.php#数字，按该锚点所在行读取等级，不点击升级。做种积分独立解析并进入第六个 profile 字段，概览十列表格。refreshOnly 默认 false，加入设置备份；后台手动、调度及内容脚本点击前均检查。启用站点在该模式下排入现有串行队列，自动总开关关闭也可执行这一次刷新，结束关闭自建标签。

0.4.7 修正：移除全局 refreshOnly 及 refresh-settings 消息。仅刷新放在站点管理每一行，用 site-settings 更新 sites[siteId].refreshOnly，默认 false；启用和仅刷新更新各自字段并保留另一个开关。共用 scheduleConfig 仍只含四项时间参数。备份每站保存 enabled/refreshOnly，旧备份缺少字段默认为 false。后台和内容脚本查当前站点，启用已设置仅刷新的站点或对启用站打开仅刷新，串行排入一次刷新；所有新建任务页按已有所有权关闭。

0.4.8 实现：site-rules.js 集中声明特殊站点规则，52PT 使用已核对的 User_Name 本人选择器、旧签到入口别名和签到赚魔力标签；只读核验 /bakatest.php 的当前结果，滑块显示需处理，“打开”转至当前签到页供用户完成。资料页按“传输”行嵌套单元格内的字段读取分享率/传输及图片等级；缺少做种积分时保持未知。页面通信采用 netsurf-inspect/netsurf-signin，旧页面脚本不会响应新协议；版本标记允许更新后重新注入，后续替换时撤销原监听器及观察器。52PT 内置 refreshOnly=true，设置归一化、单站保存、还原及内容脚本都执行；站点管理固定开关 On 且不可关闭，普通站点仍默认 Off 并可独立调整。
